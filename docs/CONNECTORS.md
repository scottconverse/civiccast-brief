## Account read fields and limits

CivicPlus Essential uses provider `municode-meetings`, origin `https://meetingsgov.devmunicode.com` (the documented dev host only), and an explicit application-owned namespace. TelVue uses provider `telvue`, origin `https://connect.telvue.com`, and an explicit account namespace. Leave their source `options` empty unless configuring an existing SDK-supported download origin; do not put credentials in source options, saved files, fetch forms or request JSON.

Essential fetch fields are `api_resource: meeting|item|multimedia` with a supplied `external_id`, or `api_resource: collection` with explicit nonnegative `offset` and exact `filters`: `Words`, `CreatedMeetingFromDate` and `CreatedMeetingToDate` (each `{Day, Month, Year}` integers), `ArchivedState` (`-1`, `0`, `1` or `2`), and `MeetingTypeIds` string array. No offset stride or response envelope is guessed. Meeting/item/collection responses whose schema is undocumented remain exact raw partial captures without inferred normalized meetings. Multimedia preserves the documented structure and supplied parent meeting relationship. No exact native text-search semantics are claimed for Words.

TelVue fetch fields are `api_resource: media|videos|playlists`; only media and playlists accept an optional decimal `external_id`. The SDK preserves transcript text, chapters, provider IDs, source metadata and unknown fields. API listing pagination/end conditions and account visibility remain unverified. A media upload date is not inferred to be a meeting date.

Trusted Essential credential configuration is keyed by `municode-meetings` and requires `origin`, `tenant`, exact `namespace` (or `allowed_namespaces` list), and `token`. TelVue is keyed by `telvue`, with the same binding fields plus `access_key` and `secret_passphrase`. `tenant` must exactly match this application's context tenant described below. Both APIs fail closed for mismatched origin, tenant, namespace, revoked grants and redirects. No token is issued by these consumers, and no test account credentials are included.

Wistia uses `https://api.wistia.com/modern/medias`, its existing SDK-derived namespace, optional source `options.page_size` and `options.folder_id`, and private `wistia_token`. The SDK offers media listing/detail, supplied captions, and bounded native media/transcript-excerpt search; consumer search screens described here search captured local records. Neither complete transcript availability nor live account acceptance is implied. Legistar read credentials use `legistar_token`; Repository v2 reads use `laserfiche_token`. Provider write credentials are separate provider dictionaries governed by server policy.

## Configure and use Brief

Run `uv sync --locked` from this repository. The vendored wheel is installed in the project environment; no shared service or Townlight Runtime is started. Start the existing local review desk with `uv run python -m civiccast_brief.review serve --db PATH --city CITY_FOLDER`. The Sources page offers kind `connector`, provider, URL, optional namespace, supported baseline or additional SDK-advertised saved input format, city-relative capture, bodies, and validated options JSON. Source configuration remains in the city's `sources.json`; connector state/evidence lives under `.connectors/state.db`. Saved captures must resolve inside the city folder, including junction checks. Normal source bodies/date windows remain consumer selections rather than completeness claims.

The Connectors page supports discovery into the existing weekly/producer pipeline, exact local phrase search, evidence export and separate explicit write planning/commit/receipts. Its Authorized account fetch form accepts only the documented `api_resource`, `external_id`, `offset` and `filters` fields above. Account captures without a known meeting/date remain evidence; they do not invent a completed meeting recap.

Pass private credentials through an operator-selected environment variable using `--connector-credentials-env NAME` on the desk or `--credentials-env NAME` on `python -m civiccast_brief.connectors`. The environment variable contains the trusted SDK credential JSON object. Brief derives its account context tenant as SHA-256 of the case-folded resolved city-folder path; operators can inspect `CivicSources(city).context.tenant` locally before configuring the exact credential binding. Do not share or commit the credential values. `CivicSources(city, credentials=...)` is the equivalent in-process integration.

The connector CLI supports discover/search/export/plan/commit/receipt; account fetch is available through the local desk and `CivicSources.fetch_account`, not a guessed CLI command. Discovery requires source ID, explicit first/last dates and review DB. Exports use `--out` and refuse to overwrite existing files. ZIP/JSON/JSONL retain exact captures and consumer evidence; CSV/iCalendar are projections with losses. Document extraction, captions, metadata-only evidence, source failures and producer edits keep their existing distinctions. Supplied recording bytes are retained as evidence and in attachment-inclusive exports; recording-only input does not imply a transcript or completed recap. A captured attachment on another origin requires an explicit `options.download_origins` list of exact HTTP(S) origins.

Provider writes are disabled unless the operator explicitly enables the separate controls (`--connector-writes` on the desk or `--enable-writes` on the connector CLI) with suitable private server policy. Planning does not mutate; commit requires the exact reviewed plan hash, and ingestion does not call commit. Receipt retrieval uses the same explicitly enabled write controls and current provider credential authorization. A configured synthetic native-adapter check covers plan, producer/hash guards, commit/readback, duplicate suppression and receipt retrieval; live test-tenant acceptance remains not run. Source evidence enters review with checks incomplete; approval and existing publication flows are unchanged.

The dev8 package retains the original formats and adds bounded current public layouts/search forms, with 28 additive parser hooks. These apply to evidenced source routes and preserve partial coverage, unknown fields and mixed record kinds; they do not establish complete upstream catalogs or live vendor write acceptance. The unchanged application review, durable record, restart and export workflows retain their earlier acceptance evidence; the exact dev8 installed checks are recorded separately.

Dev8 corrects stale implementation labels for already-implemented routes. Executable SDK modules equal dev7 except the version label and capability data; existing dev7 application-workflow evidence is reused with targeted installed version/capability checks. This metadata correction does not promote complete catalog or live write acceptance.
